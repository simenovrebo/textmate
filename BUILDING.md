# Building TextMate

TextMate is built with [ninja][]. The `build.ninja` file is generated by `bin/rave` from the `*.rave` files in the source tree. `./configure` checks dependencies, builds vendored libraries, and runs `bin/rave` for you.

## Quick Start

```sh
brew install boost cmake google-sparsehash multimarkdown ninja ragel

git clone --recursive https://github.com/textmate/textmate.git
cd textmate
./configure && ninja TextMate/run
```

With MacPorts instead of Homebrew:

```sh
sudo port install boost cmake multimarkdown ninja ragel sparsehash
```

Requirements: macOS with Xcode 26 or later (the minimum deployment target is macOS 11).

## ./configure

`./configure` does the following:

1. Finds dependencies in Homebrew’s prefix (`/opt/homebrew` or `/usr/local`) or MacPorts (`/opt/local`), and lists everything missing.
2. Builds [Cap’n Proto][capnp] from the `vendor/capnp/vendor` submodule as universal static libraries plus the `capnp` compiler (only rebuilt when the submodule changes).
3. Writes `local.rave` with the paths it found. This file is not under version control, and it is never overwritten: delete it to have `./configure` write a new one, or edit it to customize your build.
4. Runs `bin/rave` to generate `build.ninja` with default config `release` and default target `TextMate`.

Options:

- `--universal`: build release binaries for both arm64 and x86_64 (the default is the architecture of your Mac).

The build directory is `~/build/<name of source directory>` unless you set `builddir`, for example `builddir=/tmp/tm ./configure`.

You only need to run `./configure` again if you change dependencies or delete `local.rave`. Changes to `*.rave` files are picked up by `ninja` automatically.

## Build Targets

Every target has a `release` and a `debug` config. Target names without a config use the default config (`release`):

```sh
ninja TextMate               # Build and sign TextMate.app
ninja TextMate/run           # Build, sign, and (re)launch TextMate
ninja TextMate/debug/run     # Same, but debug config (address sanitizer, OakDebug)
ninja mate                   # Build a single executable
ninja -t targets | grep run  # List runnable targets
ninja -t clean               # Remove build output (or delete the build directory)
```

When building from within TextMate (⌘B with the [Ninja bundle][NinjaBundle]) the target is chosen by `TM_NINJA_TARGET` in `.tm_properties`, see README.md.

## Rave Files

Each framework, application, and plug-in has a `default.rave` describing one target. The top-level `default.rave` sets global flags and loads all the others, plus `local.rave`.

A typical framework:

```
target "${dirname}" {
	require    text cf io
	headers    src/*.h
	sources    src/*.{cc,mm,rl,capnp}
	frameworks CoreFoundation
	libraries  sqlite3
}
```

`${dirname}` is the name of the directory containing the rave file, so the target above is called `plist` when it lives in `Frameworks/plist`. Relative paths are relative to that directory. Other targets include its headers as `#include <plist/header.h>`.

An application adds a bundle layout:

```
target "${dirname}" {
	prefix "${target}.app/Contents"
	# Compile and copy resources into Contents/Resources
	files  resources/* "Resources"
	# @name refers to the output of another target
	copy   @Dialog     "PlugIns"
	sources    src/*.mm
	executable "MacOS/${target}"
	frameworks Cocoa
}
```

### Directives

| Directive | Meaning |
|---|---|
| `target NAME { … }` | Define a target. |
| `extend NAME { … }` | Add to a target defined elsewhere (typically in `local.rave`). |
| `config NAME { … }` | Only applies to the given config, e.g. `release` or `debug`. |
| `arch NAME… { … }` | Build once per architecture and merge the result with `lipo`. |
| `load GLOB…` | Load more rave files. |
| `set VAR "value"` | Set a variable (visible to nested blocks and to the targets it applies to). |
| `add VAR "value"` | Append to a variable, space separated. |
| `capture VAR "shell command"` | Set a variable to the output of a shell command. |
| `expand VAR FILE` | Run `FILE` through variable expansion and set `VAR` to the resulting path. |
| `sources GLOB…` | Files to compile: `.c`, `.m`, `.cc`, `.mm`, ragel (`.rl`), and Cap’n Proto (`.capnp`). |
| `headers GLOB…` | Public headers, exported as `<target>/<header>`. |
| `require TARGET…` | Link with (and use the headers of) other targets. |
| `require_headers TARGET…` | Only use the headers of other targets. |
| `prelude GLOB…` | Precompiled header prepended to every source file. |
| `frameworks NAME…` | System frameworks to link with. |
| `libraries NAME…` | Libraries to link with (`-lNAME`). |
| `executable PATH` | Link an executable (relative to `prefix`, if set). A target without one is a library: its object files are linked into every target that requires it. |
| `prefix PATH` | Output directory for a bundle, e.g. `"${target}.app/Contents"`. |
| `files SOURCE… DEST` | Copy files to `DEST` inside the bundle, compiling them first where applicable: `.xib` → `.nib`, `.xcassets` → `Assets.car`, `.strings` → UTF-16, `.md` → `.html`, and `Info.plist` variable expansion. |
| `copy SOURCE… DEST` | Copy files or directories unmodified. |
| `define NAME "shell command"` | Add a custom action, built with `ninja <target>/NAME`. Its output is available to other defines as `${NAME}` (see `local-orig.rave`). |
| `notarize PROFILE` | Add a `NAME/notarize` target, using a keychain profile created with `xcrun notarytool store-credentials PROFILE`. |
| `tests GLOB…`, `cxx_tests GLOB…` | Test sources. These are parsed but no test targets are currently generated. |

Comments start with `#` and must be on a line of their own.

### Variables

Flags are passed via variables, see the top-level `default.rave`: `FLAGS` (all compilers), `C_FLAGS`, `CXX_FLAGS`, `OBJC_FLAGS`, `OBJCXX_FLAGS`, `LN_FLAGS` (linker), `IB_FLAGS` (ibtool), `AC_FLAGS` (actool), `CS_FLAGS` (codesign), `CS_IDENTITY`, `PLIST_FLAGS` (Info.plist expansion), `MD_FLAGS` (markdown), `RAGEL_FLAGS`, and `CAPNP_BIN` (directory with the `capnp` compiler).

`APP_MIN_OS` in `default.rave` sets the minimum macOS version for everything, including `LSMinimumSystemVersion` and the vendored libraries.

### local.rave

`local.rave` is loaded by the top-level `default.rave` and is the place for machine specific settings. `local-orig.rave` shows the setup used for official releases (universal build, notarization, and release actions). For example, to sign with your own certificate:

```
set CS_IDENTITY "Developer ID Application: Your Name (TEAMID)"
```
